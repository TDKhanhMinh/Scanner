# Attendance Scanner V1.0 Baseline

This document freezes the V1 implementation before Version 2 scanner-engine work.
It is a compatibility and rollback reference, not a production approval by itself.

## Baseline identity

- Product baseline: `V1.0`
- Git tag: `v1.0.0`
- Baseline commit: `d83ebad20da39bf9ac906a0f3617154e33cf3aa1`
- Commit subject: `feat(scanner): add smart document scan mode`
- Package/artifact version: `0.1.0`
- Target: `x86_64-pc-windows-msvc`
- Offline mode: enabled
- State location: `APPDATA/attendance-scanner/state`

The product baseline label `V1.0` is intentionally recorded separately from the
current package version `0.1.0`. Version 2 must define the package-version policy
before publishing a new installer line.

## Compatibility contracts for V2

| Contract | V1 behavior | V2 requirement |
| --- | --- | --- |
| Input discovery | Employee folders and supported image extensions are discovered deterministically. | Preserve paths, collision handling, and unsupported-file behavior. |
| Incremental state | Manifest tracks source metadata/hash, output paths, status, period, page identity, and pipeline version. | Add detector/model metadata backward-compatibly and reprocess only by explicit policy. |
| Scan modes | `gray`, `bw`, `color`, and `smart_document` are accepted by the local pipeline. | Preserve existing modes and their output contracts. |
| PER_IMAGE export | One source page produces one deterministic PDF. | Preserve naming, atomic replacement, and output collision behavior. |
| GROUPED export | Ordered pages produce one multi-page PDF per employee/period. Ambiguous order requires review. | Preserve page identity review, manual order, and stale-artifact safeguards. |
| Page ordering | Attendance pages are ordered by detected page identity, never filename or mtime. | Preserve `TL -> TR -> BR -> BL` and page-order semantics. |
| PDF output | A4 landscape output with preserved image aspect ratio and atomic commit. | Perspective V2 must not introduce silent crop or invalid output. |
| Sidecar protocol | JSONL events use protocol version `1`; Tauri forwards structured arguments. | Keep protocol compatibility or version any breaking change explicitly. |
| Runtime locality | Python sidecar, images, state, and PDFs remain local; no cloud inference. | AI/ONNX inference must remain local and offline. |

## Rollback procedure

1. Checkout or build from the immutable `v1.0.0` tag.
2. Rebuild the sidecar and Windows bundles with the locked dependencies:
   `pwsh -NoProfile -File .\scripts\build-windows.ps1`.
3. Keep the existing input root and state directory backed up before switching
   binaries; use a separate output root when comparing V1 and V2 results.
4. If a V2 manifest entry has a newer pipeline/model version, let the V1
   pipeline classify it as outdated and rebuild the output rather than reusing
   the V2 artifact.

Rollback is a forward operational choice: it must not rewrite shared Git history
or delete user PDFs automatically.

## Gate classification

Blocking for the V1 baseline:

- Baseline tag and commit identity are stable.
- Python, frontend, and Tauri unit/regression suites pass.
- Lint, format, typecheck, frontend build, and Windows bundle build pass.
- Release manifest hashes match the generated artifacts.

Still open or limited:

- Packaged sidecar smoke/relaunch with a representative image corpus was not run.
- Packaged desktop launch, live sidecar event stream, and Open Output Folder need
  a real packaged-app acceptance run.
- No clean-machine installation/uninstallation test was performed in this task.

These open gates prevent a production-approved claim, but do not invalidate the
source-level V1 baseline tag and reproducible build record.
